### на разработку программы «Модуль математических вычислений с отладочной диагностикой» (ГОСТ 19.201-78)

### Введение
Полное наименование программного продукта: «Модуль математических вычислений с отладочной диагностикой». Краткое наименование программы: «DebugCalcApp».  
Область применения: разработка надежных модулей вычислений в автоматизированных информационных и расчетных системах, требующих непрерывной диагностики состояния и протоколирования ошибок.

### 1. Основание для разработки
Работа ведется на основании учебного плана дисциплины «Инструментальные средства разработки программного обеспечения» (ИСРПО) и индивидуального практического задания №12.  
Организация, утвердившая документ: кафедра информационных систем и программирования.  
Наименование темы разработки: «Применение отладочных классов и составление ТЗ на программный продукт».

### 2. Назначение разработки
* **Функциональное назначение:** выполнение итерационных целочисленных вычислений с динамическим контролем корректности инвариантов посредством встроенных средств диагностики (.NET Diagnostics).
* **Эксплуатационное назначение:** эксплуатация конечным оператором и инженером-программистом для тестирования и анализа отказоустойчивости программных модулей.
* **Критерии эффективности и качества:** интуитивная прозрачность, надежность работы при возникновении исключений деления на ноль, автоматическое сохранение трассировочных логов в файл `debug_trace.log`.

### 3. Требования к программе

#### 3.1. Требования к функциональным характеристикам
Программа должна обеспечивать возможность выполнения перечисленных ниже функций:
1. Инициализацию слушателей отладочных сообщений (`TextWriterTraceListener`) с дублированием логов в консоль и внешний файл `debug_trace.log`.
2. Выполнение итерационного цикла с шагами от 1 до 5 с накоплением произведения $y = i \cdot multiplier$ и суммы $sum$.
3. Контроль входных и выходных параметров с помощью отладочного класса `Debug.Assert` (проверка $multiplier > 0$ и итоговой суммы $sum == 30$).
4. Условный вывод отладочной информации `Debug.WriteLineIf` на контрольных шагах итерации.
5. Безопасное выполнение операции деления $a / b$ в защищенном блоке `try-catch-finally` с перехватом `DivideByZeroException` при $b = 0$ и протоколированием через `Trace.TraceError`.

#### 3.2. Требования к надежности
* Надежное функционирование программы обеспечивается механизмом структурированной обработки исключений `try-catch-finally` и диагностическими проверками `Debug.Assert`.
* При возникновении критических математических отказов (деление на ноль) программа не должна аварийно завершаться; время восстановления работоспособности после локализации ошибки должно составлять не более 1 минуты.

# Раздел II. Практическая реализация и применение отладочных классов

### Исходный код программы (`Program.cs`)

```csharp
using System;
using System.Diagnostics;
using System.IO;

namespace _10_11
{
    internal class Program
    {
        static void Main(string[] args)
        {
            Console.OutputEncoding = System.Text.Encoding.UTF8;

            // Настройка слушателя отладочных сообщений для вывода классов Debug и Trace в консоль и файл
            Trace.Listeners.Add(new TextWriterTraceListener(Console.Out));
            Trace.Listeners.Add(new TextWriterTraceListener("debug_trace.log"));
            Trace.AutoFlush = true;

            Console.WriteLine("==========================================================");
            Console.WriteLine("  Практическая работа №12: Применение отладочных классов");
            Console.WriteLine("==========================================================\n");

            Debug.WriteLine("[DEBUG]: Старт программы и инициализация отладочных слушателей.");

            // 1. Итерационный цикл и диагностические утверждения (Debug.Assert, Debug.WriteLine)
            int sum = 0;
            int multiplier = 2; // Переменная для изменения «на лету» в окне Watch

            // Проверка входного инварианта с помощью отладочного класса
            Debug.Assert(multiplier > 0, "Множитель multiplier должен быть строго больше 0!");

            Console.WriteLine("--- 1. Итерационный цикл с отладочными проверками ---");
            for (int i = 1; i <= 5; i++)
            {
                // Точка останова #1: клавиша F9
                int y = i * multiplier;
                sum += y;

                // Отладочный вывод по условию (Debug.WriteLineIf)
                Debug.WriteLineIf(i == 3, $"[DEBUG]: Достигнут контрольный шаг i = {i}, текущая sum = {sum}");

                Console.WriteLine($"Шаг {i}: i = {i}, y = {y}, sum = {sum}");
            }

            // Утверждение проверки корректности накопления суммы
            Debug.Assert(sum == 30, $"Ожидаемая сумма 30, но получено: {sum}");

            // 2. Демонстрация изменения переменной в отладчике
            Console.WriteLine("\n--- 2. Проверка изменения переменной multiplier ---");
            if (multiplier > 10)
            {
                Trace.WriteLine($"[TRACE]: Значение переменной изменено в процессе отладки на: {multiplier}");
                Console.WriteLine($"[УСПЕХ] Значение multiplier было изменено в отладчике на: {multiplier}!");
            }
            else
            {
                Console.WriteLine($"Обычный режим: значение multiplier = {multiplier}");
            }

            // 3. Диагностика исключений с помощью Trace и Debug.Assert
            Console.WriteLine("\n--- 3. Применение отладочных классов при обработке ошибок ---");
            try
            {
                int a = 10;
                int b = 0; // делитель равен 0

                Trace.WriteLine($"[TRACE]: Подготовка к делению a={a} на b={b}...");

                // Отладочное утверждение перед критической операцией
                if (b == 0)
                {
                    Debug.WriteLine("[DEBUG WARNING]: Зафиксирован нулевой делитель перед вычислением!");
                }

                int result = a / b; // вызов исключения DivideByZeroException
                Console.WriteLine($"Результат: {result}");
            }
            catch (DivideByZeroException ex)
            {
                Trace.WriteLine($"[TRACE ERROR]: Перехвачена ошибка времени выполнения: {ex.Message}");
                Console.WriteLine($"[Блок catch]: Ошибка! Деление на ноль невозможно ({ex.Message})");
            }
            finally
            {
                Trace.WriteLine("[TRACE]: Завершение блока вычислений и освобождение ресурсов.");
                Console.WriteLine("[Блок finally]: Ресурсы освобождены, блок завершил работу.");
            }

            Debug.WriteLine("[DEBUG]: Завершение работы программы.");
            Console.WriteLine("\nПрограмма успешно завершена.");
        }
    }
}
```

## ❓ Ответы на контрольные вопросы

### 1. Назначение технического задания?
**Техническое задание (ТЗ)** — это основополагающий технический документ, который четко определяет цели, функциональное назначение, требования к программному продукту, условиям его эксплуатации, надежности, аппаратной платформе, этапам разработки и порядку проведения приемо-сдаточных испытаний. ТЗ является юридической основой договора между Заказчиком и Исполнителем и главным критерием соответствия готового продукта предъявляемым требованиям.

### 2. Кто составляет и утверждает ТЗ?
ТЗ составляется совместной рабочей группой специалистов: техническим писателем, системным аналитиком и ведущим программистом (со стороны Исполнителя) на основе требований и предметной области Заказчика. Утверждает ТЗ уполномоченный представитель руководства Заказчика (директор, начальник технического департамента) с проставлением подписи и печати, а согласовывает технический руководитель компании-разработчика.

### 3. На каком этапе разработки программного изделия составляется ТЗ?
Техническое задание составляется на самой первой стадии жизненного цикла разработки ПО — стадии **«Разработка технического задания»** (предпроектная стадия). Согласно ГОСТ, непосредственное рабочее проектирование, кодирование и тестирование начинаются только после утверждения и подписания ТЗ.

### 4. Какими документами регламентируется написание ТЗ?
В РФ составление ТЗ на программы регламентируется государственным стандартом **ГОСТ 19.201-78 «Единая система программной документации (ЕСПД). Техническое задание. Требования к содержанию и оформлению»**. Для автоматизированных систем также применяется ГОСТ 34.602-89, а общие правила оформления документов регламентируются ГОСТ 19.106-78.
